- 원문 코드·로그를 다시 타이핑하지 않는 `source_report.py` 조립·대조 도구와 선택형 `technical-report` 조판을 추가했습니다. 설명·도식 의미의 검토와 고정 명세의 바이트 재현성 검증을 구분합니다.
- 감사 반례를 회귀 테스트로 고정했습니다. 중첩 Schema 검증, 경로 충돌, 본문·표 셀·그림 누락, 다중 섹션 참조, 초안 표시, 날짜와 문체 경고를 처리합니다.
- v1 입력을 유지하며 v2 사실 계약·의미 블록·기관별 표현 토큰을 추가했습니다. 절차형·단층 추진체계형·역할별 순서 표를 편집 가능한 한글 표로 만듭니다.
- 범용 Markdown 그림은 실제 BinData·매니페스트·그림 개체로 등록합니다. 사용하지 못하는 자원을 대체텍스트로 바꾸어 성공 처리하지 않습니다.
- 독립 한컴 워커와 시간 제한, 별도 PDF/PNG 렌더 명령을 추가했습니다. 미수행 시각 검토는 not_run으로 남습니다.
- 표 높이 보정은 명시적 선택 시 최대 2회이며, 병합 행과 본문 의미를 변경하지 않습니다.
- 원샷 내부의 연쇄 Python 실행과 중복 ZIP 저장을 줄였습니다. 고정 입력 엔진 측정은 모델 생성·한컴 렌더 시간을 포함하지 않습니다.
- Luna(low)와 Astra(high)의 AX 특강 문서 제작을 각각 1회 비교했습니다. 요구를 도식으로 해석하는 차이와 수정 필요가 관찰되어, 모델 간 일관성이나 일반적인 무결점 조판을 보장하지 않습니다.
- 모델 평가에서 발견된 Windows 콘솔 UTF-8 출력 실패와 장 번호 한 글자의 줄 수 과대 추정을 수정했습니다. 도식 선택 및 마지막 쪽 검토 지침을 명확히 했습니다.

# v1.17.0 — 개조식 보고서 문체 규칙과 검문기 (2026-08-22)

서식이 맞아도 **문체가 다르면 그 부서 문서로 안 보입니다.** v1.16.0 에서 서식을
익힌 지자체 실무부서 보고서 15건(2,288줄)을 이번에는 문체로 다시 재서, 규칙 문서와
검문기를 넣었습니다.

## 실측 — 이 문체는 개조식이다

| 규칙 | 실측 |
|---|---|
| `~다 / ~이다 / ~한다` 서술형 종결 | **0%** (항목 0/264, 세부 1/305, 결론 0/23) |
| `A가 아니라 B다` 식 수사 | **0건** — `아닌` 12건은 전부 두 구체 선택지를 가르는 것 |
| 물음표·느낌표 | 본문 0 |
| ❍ 항목 / - 세부 / ⇒ 결론 길이 | 중앙 31 / 48 / 30자 |
| 종결 꼴 | 명사(`필요·운영·조성·가능·지원`) 대부분, `~함/있음` 세부 16% |
| (괄호 소제목) | 항목의 12% — 문제점·추진방향 장에 4~5개씩 |
| 리드문 | `~하고, ~하여 ~하고자 함.` 한 문장 |

판별법 하나: `~가 아니라 B`에서 **B가 제도·장소·절차면 되고, 사람·본질·전환 같은
추상어면 수사**입니다. `references/bogo-munche.md` 에 통계·예문·검문표를 적었습니다.

## 검문기 — `scripts/munche_lint.py`

```bash
python3 scripts/munche_lint.py 원고.md     # 위반(error) 있으면 exit 2 — 고친 뒤 조판
```

LLM 이 잘 빠지는 버릇을 잡습니다 — 서술형 종결(`~해야 현장에 남는다`), 수사적 대조
(`도구가 아니라 사람이다`), 대구 슬로건(`가르치는 일은 사람이, 반복되는 일은 AI가`),
줄표 덧붙임(`— 설명`), 긴 항목, 리드문 종결, 날짜·금액 표기. 내 초고에서 6건,
스킬 샘플 2종에서 3건이 실제로 잡혀 고쳤습니다 — 이 릴리즈의 샘플은 검문 0건입니다.

워크플로우 Y(요약보고·기본계획)에 **조판 전 문체 검문** 단계를 넣었습니다 — 내용
에이전트가 `bogo-munche.md` 를 읽고 쓰고, 행정병에게 넘기기 전에 검문기를 돌립니다.
