# docket

개발 폴더 하나를 프로젝트로 등록하고, 고칠 것을 포스트잇처럼 적어 두면 Claude Code 가 코드를 읽고 계획을 세운다.
사용자는 계획을 승인하거나 의견을 달고, 구현 결과를 보고 완료하거나 수정을 요청한다. 이슈의 단계만 관리하면 된다.

Rust(Tauri 2) · React 19 · shadcn/ui(Radix) · Tailwind 4.

## 이슈의 단계

| 단계 | 들어오는 길 | 사용자가 하는 일 |
| - | - | - |
| 메모 | 보드 맨 위 작성칸 (Ctrl+N) · 스크린샷 붙여넣기 · 파일 끌어 놓기 | 계획 세우기, 또는 자동 계획을 켜 두고 기다리기 |
| 계획 | Claude 가 읽기 도구만으로 코드를 보고 계획 · 바꿀 파일 · 주의할 점 · 확인할 것을 낸다 | 승인하고 구현 · 다시 계획(의견) · 보류 |
| 구현 | 계획 때의 Claude 세션을 이어 구현한다. 바뀐 파일과 변경분이 그때그때 쌓인다 | 완료 · 수정 요청 |
| 완료 · 보류 | | 다시 열기 · 산출물로 남기기 |
| 되돌리기 | 결과 확인 · 완료 단계의 「되돌리기」, 또는 더 보기 메뉴의 「구현 되돌리기」 | 기록한 변경분을 넘겨 같은 세션의 Claude 가 거꾸로 고친다. 새로 만든 파일은 앱이 휴지통 폴더로 옮긴다. 끝나면 계획 단계로 돌아간다 |

- **걸러 보기**: 보드 위 검색칸(Ctrl+F)은 `#번호` · 제목 · 메모 · 계획 · 결과 · 바뀐 파일 경로에서 찾는다. 제목 밖에서 찾았으면 카드에 찾은 곳과 그 앞뒤를 보인다. 칩은 단계를 가로질러 내 차례 · 실행 중 · 실패 · 코드 바뀜만 남기고, 정렬은 결정할 것 먼저 · 최근 움직인 순 · 번호 큰 순이다. 찾는 중에는 보류한 메모도 함께 보인다. 「기간」은 움직인 날 또는 만든 날로 오늘 · 최근 7일 · 최근 30일 · 직접 고른 날짜 사이만 남긴다. 거른 조건은 프로젝트마다 앱을 끌 때까지 기억한다.
- **어디로든 가기**: Ctrl+K(입력칸 안에서도)로 모든 프로젝트의 이슈 · 대화 · 산출물 · 프로젝트 · 화면 · 설정 항목을 번호 · 제목으로 찾아 연다. 본문은 보지 않는다 — 본문은 보드 검색칸에서 찾는다. 비워 두면 최근 연 것과 결정할 차례 이슈를 보이고, 자음만 치면 초성으로 찾는다.
- **우클릭 메뉴**: 보드 카드 · 사이드바 프로젝트 · 대화 목록 · 산출물 목록과 판 · 템플릿 · 메모 첨부 · 바뀐 파일 머리 · 결과 화면 · 실행 중 작업 · Claude 설정 목록에서 그 대상의 동작을 연다. 「더 보기」 메뉴와 같은 항목을 같은 조건으로 보이고, 카드에는 카드 단추와 같은 단계 동작(계획 세우기 · 승인하고 구현 · 완료 · 중지 · 다시 열기)과 번호 · 제목 복사를 더한다. 설치한 앱에서는 그 밖의 자리에서 WebView 기본 메뉴(뒤로 · 새로 고침 · 인쇄)를 막는다. 입력칸 · 편집기 · 고른 글 위에서는 기본 메뉴가 그대로 뜨고, 개발 실행은 「검사」를 쓰도록 막지 않는다.
- **여러 개 고르기**: 보드 카드를 Ctrl 클릭하면 하나씩 넣고 빼고, Shift 클릭하면 마지막으로 누른 카드부터 화면 순서(열 왼쪽부터, 열 안은 위부터)로 범위를 고른다. Ctrl+A 는 보이는 카드를 모두 고르고 Esc 는 푼다. 고른 것이 있으면 보드 위 줄과 고른 카드의 우클릭 메뉴에서 한 번에 보류하거나 지운다 — 실행 중인 카드는 빼고, 보류는 완료 · 이미 보류한 카드도 뺀다. 그냥 클릭하면 고른 것이 풀리고 그 카드가 열린다. 걸러 보기로 안 보이게 된 카드는 고른 것에서 빠진다.
- **키보드로 보드 다루기**: Tab 으로 보드에 들어가면 카드 하나에 멈추고, ← → 로 열 · ↑ ↓ 로 카드를 옮긴다. 열을 옮기면 같은 순번의 카드로 간다. Enter 는 열기, Ctrl+Enter 는 카드에 보이는 단추 누르기(중지는 1.5초 안에 두 번), C 는 번호 복사, Shift+F10 · 메뉴 키는 우클릭 메뉴다. 키보드로 초점이 간 카드는 Ctrl+Enter 로 눌릴 단추에 테두리를 켠다. 검색칸에서 ↓ 는 첫 카드로 간다. 키 목록은 ? 로 연다.
- **완료 숨기기**: 보드 위 단추로 완료 열을 접고 나머지 세 열을 넓힌다. 숨긴 건수는 단추에 보인다. 이것은 프로젝트마다 앱을 다시 켜도 남는다.
- **자동 계획**: 메모를 마지막으로 고친 뒤 정한 시간(기본 60초)이 지나면 계획을 시작한다. 실패했거나 사용자가 중지한 이슈는 다시 건드리지 않는다.
- **제목**: 메모에 제목을 따로 적지 않아도 된다. 메모를 붙이거나 고친 뒤 5초가 지나면 설정의 「제목 모델」(기본 Haiku)이 본문을 읽고 제목 한 줄을 지어 붙인다. 지어 오기 전과 짓지 못했을 때는 첫 줄을 제목으로 보인다. 상세 창에서 제목을 누르면 손으로 고칠 수 있고, 고친 제목은 메모를 바꿔도 남는다. 비우면 다시 모델이 짓는다. 제목 모델을 끄거나, 이 기능 전에 만든 메모이거나, 프로젝트 대화가 제목을 붙여 등록한 메모이면 첫 줄이 제목이다.
- **메모 모델 · effort**: 메모를 붙일 때 작성칸에서, 붙인 뒤에는 상세 창의 메모 탭에서 그 메모에 쓸 모델과 effort 를 단추 하나로 고른다(열면 왼쪽이 모델, 오른쪽이 effort). 고른 값은 그 메모의 계획 · 구현 · 대화에 모두 쓰이고 설정의 실행별 값보다 앞선다. 모델과 effort 는 따로 따른다 — 모델만 골랐으면 effort 는 설정을 따른다. 「설정 따름」이면 실행 종류에 맞는 설정 값을 쓴다. 바꾼 값은 다음 실행부터 쓰이고, 계획 탭 머리에 그 계획을 세운 모델 · effort 가 보인다.
- 구현 · 수정 요청 · 되돌리기 · 파일로 만드는 산출물은 한 프로젝트 안에서 줄에 선다. 두 구현이 같은 파일을 동시에 고치지 않게 하려는 것이다.
  구현은 계획에 적힌 파일(수정 요청 · 되돌리기는 이미 고친 파일까지)을 잡고, 지금 도는 구현과 겹치지 않으면 몇 개든 함께 돈다. 함께 도는 동안 다른 구현이 잡은 파일에는 Edit · Write 거부 규칙을 걸고, 그래도 계획 밖에서 남의 파일을 고치면 실행은 그대로 두고 흐름에 「파일 겹침」을 남긴다. 계획에 폴더 · 와일드카드 · 저장소 밖 파일이 있거나 바꿀 파일이 비었거나 「모두 허용」(명령으로 쓰는 것은 거부 규칙이 막지 못한다)이면 프로젝트 전체를 잡아 한 줄로 서고, 파일로 만드는 산출물도 늘 전체를 잡는다. 겹치는 것끼리는 먼저 선 차례대로 들어가고, 대기 중 카드에 무엇을 기다리는지 보인다. 프로젝트 설정 「파일이 겹치지 않는 구현은 함께 돌리기」(기본 켜짐)를 끄면 모두 한 줄로 선다. 계획 · 대화 · 마크다운 산출물은 줄을 기다리지 않고 바로 돈다. 함께 도는 수에는 상한이 없다 — 기다릴지는 잡은 파일이 겹치는지로만 정한다. 대화는 편집 권한이어도 구현과 함께 돌 수 있어 같은 파일을 함께 고칠 수 있다. 프로젝트끼리는 따로 돈다.
  프로젝트 설정 「기다려야 할 구현은 워크트리에서 돌리기」(기본 꺼짐 · 함께 돌리기를 켰을 때만)를 켜면, 파일이 겹쳐 줄을 서야 할 첫 구현은 기다리지 않고 저장소 옆 `<저장소>.worktrees/<번호>` 에 git 워크트리를 만들어 바로 돈다. 바탕은 HEAD 가 아니라 지금 작업트리(커밋하지 않은 변경 · 새 파일 포함, .gitignore 로 빠진 것은 없음)를 임시 인덱스로 찍은 커밋이라 사용자 인덱스를 건드리지 않는다. 계획 세션 기록을 워크트리 자리로 복사해 구현이 이어 붙고, 그 이슈의 수정 요청 · 대화 · 터미널도 워크트리에서 돈다. 결과 확인의 「반영」은 바뀐 파일마다 본 작업트리가 바탕 그대로면 덮고, 그 사이 바뀌었으면 3-way 로 합친다. 하나라도 합치지 못하거나 같은 파일을 고치는 구현이 돌고 있으면 아무것도 쓰지 않는다. 반영 전에는 완료할 수 없고, 되돌리기는 Claude 를 부르지 않고 워크트리를 지운다. 반영 · 되돌리기 · 이슈 지우기 뒤에 워크트리를 지운다. 저장소가 크면 사본을 만드는 것 자체가 무거우니 켜지 않는다.
- 실행 중인 작업은 제목 줄의 「Claude 실행 N」을 눌러 모든 프로젝트에 걸쳐 보고, 하나씩 또는 모두 중지한다. 보드의 실행 중 카드에도 중지 단추가 있다.
- 실행 중에 창을 닫으면 무엇이 돌고 있는지 보여 주고 「중지하고 닫기」를 묻는다. 앱이 띄운 claude 는 Windows 작업 개체(Job Object)에 들어가 있어, 앱이 어떻게 끝나든(강제 종료 포함) 함께 꺼진다. 앱이 모르는 수정이 저장소에 남지 않게 하려는 것이다. 앱이 띄운 터미널 · 탐색기는 작업 개체 밖이라 앱을 닫아도 남는다.
- 제목 줄에 Claude 구독 사용량(「5시간 9% · 7일 32%」)이 보인다. 누르면 창마다 막대 · 다시 차는 시각 · 받은 때를 보인다. 따로 묻지 않고 실행이 돌 때 claude 가 함께 보내는 값(`rate_limit_event`)을 받아 두므로, 값은 마지막으로 claude 를 돌린 때의 것이다. 앱 밖에서 쓴 양은 다음 실행 때 반영된다. 80% 를 넘으면 노란색, 95% 를 넘거나 한도에 걸리면 빨간색이다. API 키로 쓰면 이 값이 오지 않아 보이지 않는다.
  같은 창 아래에 「이 앱이 쓴 양 · 최근 7일」이 보인다. 앱이 claude 를 부를 때마다 장부(`spend.jsonl`)에 한 줄씩 적은 것을 계획 · 구현(되돌리기 포함) · 대화 · 산출물 · 제목과 색인 카드와 판정으로 묶어 부른 횟수 · 토큰(입력 · 캐시 작성 · 캐시 읽기 · 출력의 합) · 비용을 보인다. 비용은 claude 가 API 요금으로 어림한 값이라 구독 청구액이 아니다. 실행마다의 토큰은 이력 탭 · 대화 탭의 실행 줄에도 보인다.
- 계획 · 구현 · 대화 답이 끝나면 알림이 뜨고, 창이 뒤에 있으면 작업 표시줄에서 깜빡인다. 그 대상을 이미 열어 보고 있으면 띄우지 않는다. **알림함**: 제목 줄의 종 단추가 모든 프로젝트에서 끝났는데 아직 열어 보지 않은 것(대화 답 · 계획 나옴 · 구현 끝 · 실패 · 산출물 새 판)을 수와 목록으로 보인다. 누르면 그 대화 · 이슈 · 산출물로 가고, 열면 읽음이 된다(창이 뒤에 있을 때 연 것은 앞으로 가져올 때 읽음이 된다). 「모두 읽음」 · 줄 우클릭 「읽음으로」도 있다. 대화 목록에는 읽지 않은 답에 점이 찍힌다. 중지한 실행 · 반영할 것이 없어 건너뛴 자동 갱신 · 터미널에서 이어 간 차례는 넣지 않는다. 읽음 표시는 이 PC 의 화면 저장소에만 두고, 처음 켠 때보다 먼저 끝난 실행은 읽은 것으로 본다. 결정할 이슈 수는 그대로 사이드바 뱃지가 센다.
- **그림 · 목업 · 결과 화면**: 계획 · 결과 · 대화의 마크다운은 그림을 띄운다. `attachments/` · `shots/` 는 이슈 폴더 기준이고, 나머지 상대 경로는 저장소 기준이다. 절대 경로도 된다. 저장소 안 그림은 그릴 때 그 파일 하나만 asset 범위에 연다(등록한 프로젝트 안의 그림 확장자만). ```html 블록은 화면 목업으로 그린다. `sandbox="allow-scripts"` iframe 이라 스크립트는 돌지만 앱 API 에 닿지 않고, 네트워크는 CSP 로 막는다. ```svg 블록은 그림으로 그린다. 화면 · 배치 · 흐름이 바뀌는 계획 · 대화에만 목업을 넣으라고 Claude 에게 지시한다. 화면이 바뀐 구현이면 Claude 가 방법(playwright · Edge 헤드리스 등)을 골라 결과 화면을 이슈 폴더의 `shots/` 에 찍고, 앱이 결과에 적힌 그림만 `shots/<실행>/` 으로 모아 변경 탭 「결과 화면」에 보인다. 찍기 명령은 지금 권한 체계를 따른다. 막히면 변경 탭에서 「허용」한다. 이슈 폴더 · 임시 폴더에 쓴 파일은 바꾼 파일로 남기지 않는다.

## 그 밖의 화면

- **대화**: 메모를 쓰지 않고 프로젝트에서 바로 Claude 와 대화한다. 구조를 묻는 데서 시작하므로 기본이 「읽기 전용」이다(읽기 도구 · 이력 조회만 열고 구현과 줄을 서지 않는다). 스위치를 끄면 이슈 대화처럼 고칠 수 있다. 첫 질문을 임시 제목으로 쓰다가, 첫 답이 끝나면 제목 모델이 첫 질문과 답 앞부분을 읽고 주제 한 줄을 지어 붙인다. 한 번 지은 제목은 차례가 늘어도 바꾸지 않는다. 대화 머리의 제목을 누르면 손으로 고치고, 비우면 다시 짓는다. 제목 모델을 끄면 첫 질문이 제목이다.
  - 대화는 보드에 나오지 않는 이슈로 같은 `issues/` 폴더에 둔다(`issue.json` 의 `talk`). 번호를 받지 않고 단계도 없다. 세션 잇기 · 첨부 · 터미널에서 잇기 · 바뀐 파일 기록은 이슈 대화와 같다.
  - 묻다가 「작업 메모로 등록해 줘」라고 하면 Claude 가 답 끝에 `[메모:등록] <제목>` … `[/메모]` 블록을 내고, 앱이 블록마다 보드에 새 메모를 만든다(자동 계획은 설정을 따른다). 표지 줄은 화면에서 걷어 내고, 차례 아래에 「메모 #N」 줄과 「열기」를 보인다. 닫는 줄이 없는 블록은 등록하지 않는다. 메모는 대화 세션을 잇지 않고 새로 계획하므로, 본문에 대화의 맥락을 담게 한다.
- **산출물**: 프로젝트별 보고서 · 설계서 · 캡처를 판(v1, v2 …)으로 모은다. 산출물마다 「만드는 법」을 둔다.
  - 템플릿 · 참고 자료: 끌어 놓은 파일을 Claude 가 쓸 때마다 먼저 읽는다. hwpx · docx · xlsx · pptx 는 앱이 글자를 뽑아 둔다(Claude 의 Read 가 못 읽는다). hwp 는 읽지 못한다.
  - 템플릿: 넣은 hwpx · docx · xlsx · pptx 가운데 하나를 템플릿으로 표시한다(처음 넣은 것 · 우클릭으로 바꾼다). 결과 파일 형식은 템플릿을 따른다. 오피스 파일로 새 산출물을 등록하면 그 파일을 견본으로 한 부 더 넣어 템플릿으로 삼는다. 빈 양식은 만들지 않고, 쓸 때 「목차 · 표 · 서식은 그대로 두고 내용만 바꾼다」고 지시한다.
  - 작성법: 템플릿 · 참고 자료 · 지난 판에서 뽑은 구성 · 담는 것 · 문체 · 표기 규칙(마크다운). 고칠 수 있고, 쓸 때마다 함께 넘긴다.
  - 어휘: 이 산출물에서 쓸 말 · 피할 말 · 뜻. 프로젝트 어휘 사전도 켜 두면 함께 붙고, 같은 말이면 산출물 어휘를 따른다. 칩의 「어휘 사전으로 올리기」로 사전에 옮긴다(피할 말은 사전의 비슷한 말이 된다).
  - 작성법 뽑기: 템플릿 · 참고 자료를 넣거나 새 산출물을 등록하면 Claude 가 글을 읽고 작성법 · 어휘 · 형식 · 템플릿을 뽑는다. 이름 규칙은 앱이 파일 이름(`요구사항_v3_20261001` → `{제목}_v{판}_{날짜}`)에서 짐작한다. 빈 칸은 바로 채우고, 값이 있는 칸은 제안으로만 보여 「적용」해야 바뀐다. 작성 지침은 건드리지 않는다. 구현 모델로 돌아 비용이 들고, 설정의 「파일을 넣으면 작성법 뽑기」로 끈다. 뽑은 것은 앱 데이터(`meta.json`)에만 둔다.
  - 작성 지침: 누가 읽는지 · 무엇을 담는지 · 말투. 사용자가 적는 칸이다.
  - 규칙 모아 보기: 산출물 목록 위 단추. 산출물마다 이름 규칙 · 형식 · 템플릿 · 어휘 수 · 작성법(뽑는 중 · 제안 있음)을 한 표로 본다.
  - 산출물 설정: 산출물 목록 위 단추. 산출물 폴더 · 기본 파일 이름 규칙 · 빈칸을 `_` 로 바꾸기 · 지난 판을 옮길 폴더를 정한다. 프로젝트 설정과 따로 저장해 서로 덮지 않는다.
  - 파일 형식: Claude 가 결과 파일을 직접 만든다. 형식은 정한 값 → 템플릿 확장자 → md 순이다(마크다운도 형식의 하나다). 문서 스킬을 돌리느라 명령 실행을 허용하고, 저장소 안 편집은 `Edit(./**)` · `Write(./**)` 거부 규칙으로 막는다. 명령으로 쓰는 것까지 막지는 못해 프로젝트 실행 줄에 선다.
    (2026.10.29 「마크다운으로 받기」 — 읽기 도구만 열고 앱이 답 글을 .md 로 저장하던 방식 — 를 없앴다. 형식과 방식을 따로 고를 까닭이 없었다.)
  - 파일 이름 규칙: `{제목} {판} {날짜} {시각} {프로젝트}`. 비우면 산출물 설정의 기본 규칙(기본 `{제목}_v{판}_{날짜}`). 앱이 쓰는 판에만 쓰고, 가져온 파일은 받은 이름 그대로 둔다.
  - 그 밖에 직접 쓰기, 파일 올리기, 이슈 하나를 메모 · 계획 · 결과 · 바꾼 파일 문서로 남기기.
  - 코드가 바뀌면 자동 갱신: 켜 둔 산출물은 이슈를 완료할 때 그 변경(계획 · 결과 요약 · 바뀐 파일 · 변경분 앞부분)과 관련 있는지 카드 모델이 가린다. 관련 있으면 지금 판을 바탕으로 고친 새 판을 쓰고, Claude 가 반영할 것이 없다고 답하면 판을 만들지 않는다. 판이 하나는 있어야 돌고, 코드를 고치지 않은 이슈에서는 돌지 않는다. 결과는 그 이슈의 흐름(「산출물 자동 갱신」)과 산출물의 「자동 관리」 탭에 남는다.
  - 자동 관리: 산출물 상세의 탭. 자동 갱신 스위치 · 반영 대기 · 기록(이슈마다 판정 · 작성 결과, 최근 50건)을 모은다. 반영 대기는 자동 갱신을 켜고 판이 있는 산출물에서, 코드를 고치고 완료된 이슈 가운데 기록에 반영이 끝났다고 남지 않았고 최신 판보다 뒤에 끝났거나 반영하지 못했다고 남은(작성 중이라 건너뜀 · 실패 · 중지 · 버린 판) 것이다. 저장하지 않고 목록을 읽을 때 센다. 「밀린 변경 반영」은 고른 이슈(10건까지)의 변경을 한 요청으로 묶어 판정 없이 새 판을 쓴다.
  - 검토: 자동 갱신 · 밀린 변경 반영으로 쓴 판에 「검토 필요」 표지가 붙는다. 판은 바로 최신이 되고 판 번호 · 이름 규칙은 그대로다. 「검토함」은 표지만 지우고, 「이 판 버리기」는 판 파일을 앱 데이터의 휴지통으로 옮기고 그 판이 반영한 이슈를 반영 대기로 돌린다. 글 판은 「앞 판과 비교」로 줄 단위 차이를 본다.
  - 상태: 산출물 목록의 「상태」 열은 작성 중 · 실패 · 검토 필요 · 반영 대기 N · 최신 · 수동(자동 갱신 꺼짐) · 판 없음 가운데 하나다. 「손볼 것」은 실패 · 검토 필요 · 반영 대기만 남긴다.
- **지식베이스**: 프로젝트마다 참고 문서를 모아 두면 계획 · 대화 · 산출물 작성 때 앱이 메모 · 질문 · 산출물 요청과 가까운 구획을 찾아 프롬프트에 발췌 · 경로를 붙인다. 기본은 꺼져 있다.
  - 자료: 참조 폴더(복사하지 않고 그 자리를 하위 폴더까지 훑는다) · 끌어 놓은 파일과 폴더(앱 데이터에 복사) · 산출물의 최신 판(기본으로 넣는다). 읽는 형식은 md · txt · csv · tsv · json · yaml · xml · html · sql · docx · xlsx · pptx · hwpx · pdf 다. hwp · doc · xls · ppt · 그림 · 스캔 PDF 는 읽지 못하고 까닭을 목록에 보인다. 숨은 폴더 · `node_modules` · 20MB 넘는 파일 · `.env` · 키 파일은 넣지 않는다.
  - 색인 카드: 글자를 뽑아 구획으로 나누고, 구획마다 카드 모델(기본 제목 모델)이 요약 · 핵심어 · 비슷한 말 · 답할 질문을 한 번 적어 둔다. Claude 에는 임베딩이 없어서, 뜻으로 찾게 해 두는 일을 벡터 대신 이 카드로 한다. 카드를 만들 때 문서 내용이 Claude 로 가고 호출 비용이 든다(화면에 쌓인 비용을 보인다). 바뀐 파일 · 구획만 다시 만든다.
  - 찾기: 로컬 BM25 로 카드와 원문에 점수를 매긴다(카드에 무게를 더 준다). 찾을 때는 Claude 를 부르지 않는다. 「고르기 다듬기」를 켜면 후보 30개를 카드 모델이 한 번 더 고른다. 붙인 구획은 실행 기록에 남는다.
  - 켤 때 · 10분마다 · 자료를 넣거나 산출물에 새 판이 생길 때 다시 훑는다. 「찾아보기」로 실행 때 무엇이 붙을지 미리 본다.
  - 낡은 자료: 같은 폴더에서 판 표시(`_v14` · `_20261027` · ` (1)`)를 뗀 이름이 같은 파일은 한 문서로 보고 가장 높은 판만 넣는다(판 번호가 없으면 이름 속 날짜로 견준다). 같은 판의 다른 형식은 원본 형식(docx · hwpx · pptx · xlsx)을 남기고 PDF 는 뺀다. 판 표시가 없는 파일은 순서를 알 수 없어 그대로 넣고, 수정 시각으로는 가리지 않는다. 잘못 빠진 파일은 목록의 「다시 넣기」로 되살린다.
  - 「빼는 것」에 이름 조각(`이전판`)을 적으면 참조 폴더 · 넣은 자료 안에서 그 말이 든 폴더 · 파일을, 전체 경로를 적으면 그 파일 · 폴더 아래를 넣지 않는다. 처음엔 비어 있다. 뺀 파일의 카드는 남겨 다시 넣어도 비용이 들지 않는다.
  - 붙이는 자료 블록은 「자료는 낡았을 수 있다. 지금 코드 · 메모 · 사용자의 말과 어긋나면 그쪽을 따르고, 어긋난 자료와 내용을 답에 밝힌다」고 일러 둔다.
- **어휘 사전**: 프로젝트마다 용어 · 뜻 · 비슷한 말을 적어 두면 계획 · 대화 · 구현 · 산출물 작성 때 앱이 프롬프트에 「이 프로젝트의 용어」로 붙인다. 기본은 꺼져 있고, Claude 를 따로 부르지 않아 비용이 들지 않는다.
  - 찾지 않고 사전 전체를 넘긴다. Claude 가 메모에 없는 용어를 코드에서 만나도 알게 하려는 것이다. 8,000자를 넘으면 메모 · 질문에 나온 용어부터 넣고 나머지는 자른다. 세션을 이어 받는 실행에는 다시 붙이지 않고, 되돌리기에는 붙이지 않는다.
  - 다른 프로젝트의 사전을 골라 함께 쓴다. 복사하지 않고 실행 때마다 읽으므로 그쪽에서 고친 것이 바로 반영된다. 같은 용어가 있으면 이 프로젝트의 것이 앞서고, 고른 프로젝트가 다시 고른 사전까지는 따라가지 않는다.
  - 지식베이스도 켜 두었으면 찾을 때 메모에 나온 용어의 비슷한 말을 덧붙여 찾는다. 붙인 용어는 실행 기록에 남아 이력 탭에서 「어휘 N」을 펼쳐 본다.
- **Claude 설정**: 전역(`~/.claude`)과 프로젝트의 지침(CLAUDE.md · CLAUDE.local.md · AGENTS.md) · 스킬 · 에이전트 · 명령 · 규칙을 찾아보고 고치고 만들고 지운다. 저장할 때 원래 파일의 줄바꿈(CRLF · LF)과 BOM 을 지키고, 열어 둔 사이 다른 곳에서 바뀌었으면 덮어쓰기 전에 묻는다. 지운 것은 앱 데이터의 휴지통 폴더로 옮긴다.
- **설정**: claude 실행 파일 · 계획 · 구현 · 대화 모델과 effort(기본은 모두 CLI 기본값. 산출물 작성 · 되돌리기는 구현 값을 쓴다) · MCP 서버 사용 · 자동 계획 · 플러그인 설치 · 켜기 · 권한 허락 · 설정 칸 · 테마. 프로젝트마다 구현 권한(편집만 허용 / 모두 허용, 묻지 않고 허용할 명령 · 저장소를 보고 고른 명령 후보, 막을 명령 · 경로, 계획 때 이력 조회, 전역 · 저장소 설정에서 함께 걸리는 규칙 보기)을 따로 둔다. 산출물 폴더 · 이름 규칙은 산출물 화면의 「산출물 설정」에 있다.

## 데이터는 프로젝트 밖에 둔다

이슈 · 첨부 · 계획 · 실행 기록 · 산출물은 모두 `%APPDATA%\docket` 에 저장한다. 다른 곳에 두려면 환경 변수 `DOCKET_HOME` 에 폴더를 지정한다.

```text
docket/
  settings.json · projects.json
  usage.json                              마지막으로 받은 구독 사용량
  spend.jsonl                             claude 호출마다 토큰 · 비용 한 줄 (90일만 남긴다)
  projects/<프로젝트>/issues/<이슈>/        issue.json · note.md · attachments/ · runs/<실행>.jsonl
  projects/<프로젝트>/deliverables/<산출물>/ meta.json · refs/(템플릿 · .text/ 뽑은 글자) · v1/<파일> · runs/
  projects/<프로젝트>/kb/                   catalog.json(파일 · 구획 · 카드) · inbox/(넣은 자료) · text/(뽑은 글자)
  projects/<프로젝트>/glossary.json          어휘 사전 용어 목록
  trash/                                  지운 것
  plugins/<id>/                           플러그인 (plugin.json · plugin.wasm · 옛 정의는 plugins/<id>.json)
  plugins-data/<id>/                      플러그인의 설정 칸 값 · 저장소 · 기록
```

산출물 화면의 「산출물 설정」에서 산출물 폴더를 정하면 판 파일만 그 폴더(+산출물마다 하위 폴더)에 둔다. 정보 · 템플릿 · 작성 기록은 그대로 앱 데이터에 남는다.

프로젝트 폴더에 이 앱이 스스로 만드는 파일은 없다. 프로젝트 폴더가 바뀌는 경우는 셋뿐이다.
구현 단계에서 Claude 가 소스를 고칠 때, 사용자가 Claude 설정 화면에서 그 프로젝트의 지침 · 스킬을 저장할 때, 사용자가 산출물 폴더를 프로젝트 안으로 정했을 때.
Claude 에게는 메모나 이 앱을 저장소 파일 · 주석에 언급하지 말고, 커밋 · push · SVN 쓰기를 하지 말라고 매번 지시한다.

## Claude 를 부르는 방법

`claude -p --output-format stream-json --verbose --permission-prompts none` 을 프로젝트 폴더에서 띄운다.

- 프롬프트는 표준 입력으로 넣는다. 인자로 넘기면 Windows 셸을 거칠 때 여러 줄 · 기호가 깨진다.
- npm 으로 깔면 PATH 에는 `claude.cmd` 만 보이므로 그 옆의 `claude.exe` 를 찾아 직접 부른다.
- 제목 짓기는 `--tools ""`(도구 없음) · `--no-session-persistence` · 짧은 `--system-prompt` 로 글 한 줄만 받는다. 이슈 폴더에서 띄워 저장소 지침을 읽지 않고, 파일을 고치지 않으므로 프로젝트의 실행 줄에 서지 않는다. 동시에 둘까지만 띄우고, 응답은 이슈 폴더의 `title.jsonl` 에 남는다.
- 지식베이스의 색인 카드 · 고르기 다듬기 · 자동 갱신 판정도 같은 꼴(도구 없음 · 세션 남기지 않음)로 앱 데이터 폴더에서 띄우고, 답 글에서 JSON 을 꺼낸다. 마지막 호출의 응답은 `kb/*.last.jsonl` 에 남는다.
  이 짧은 호출(작성법 뽑기 포함)은 모두 `--safe-mode` 로 띄워 사용자 전역 CLAUDE.md · 플러그인 · 훅 · 자동 메모리를 싣지 않는다. 글 한 덩이만 받는 호출인데 그것들이 실려 제목 한 번에 9.5k 토큰쯤 들었다(빼면 0.8k). `--bare` 는 구독 로그인을 읽지 않아 쓰지 않는다.
- 계획 · 구현 · 대화 · 되돌리기 · 산출물 작성은 `--settings` 의 `claudeMdExcludes` 로 사용자 전역 CLAUDE.md(`~/.claude/CLAUDE.md` · `~/.claude/rules/`)를 빼고 `autoMemoryEnabled: false` 로 자동 메모리를 끈다. 저장소 · 상위 폴더 CLAUDE.md 는 그대로 읽는다. 호출 한 번에 7.9k 토큰쯤 준다(읽기 도구 12.3k → 4.2k · 전체 도구 33.5k → 25.7k).
  사용자 설정 출처는 빼지 않는다. 빼면 사용자 `settings.json` 의 거부 규칙 · 훅까지 빠진다. 이어 붙인 세션에는 그 세션이 이미 받은 지식베이스 구획을 다시 붙이지 않는다.
- 산출물을 파일로 만들 때는 앱에 실은 플러그인(`src-tauri/claude-plugin`, 설치본의 리소스 폴더)을 `--plugin-dir` 로 싣는다. 한글 · 워드 · 엑셀 · 파워포인트는 `docket:hwpx` · `docket:docx` · `docket:xlsx` · `docket:pptx` 로 만들고, 다 쓴 글은 `docket:anti-slop` 으로 다듬는다.
  같은 일을 하는 계정 · 사용자 스킬(`anthropic-skills:docx` 등 · 사용자 `hwpx`)은 그 실행에서 거부 규칙으로 막아, 이 PC 의 Claude 에 무엇이 깔렸든 같은 꼴로 나온다.
  Python 과 `python-docx` · `openpyxl` · `lxml` · `python-pptx` · `Pillow`, 한글은 `skills/hwpx/requirements-one-shot.txt` 의 패키지가 필요하다. 스킬마다 하는 일 · 출처 · 라이선스는 `src-tauri/claude-plugin/NOTICE.md` 에 있다.
  순서는 템플릿 훑기 → 원고 쓰기 → 원고 다듬기(anti-slop 의 편집 방법 · 한국어 프로필만 읽는다) → 파일에 한 번 넣기 → 서식 · 견본 글자 견주기 → 쪽 그림 보기다.
  쪽 그림은 플러그인의 `scripts/render.py` 가 그린다(워드 · 엑셀 · 파워포인트는 LibreOffice → Office, 한글은 내장 rhwp → 한컴). 산출물 폴더의 `check/<실행 id>` 에 그리고 실행이 끝나면 지운다 — 시스템 임시 폴더는 실행 중 Read 가 막힌다.
  「설정 › 산출물 › 문서 도구」는 `scripts/doctor.py` 로 이 도구들이 있는지 점검한다.
  「설정 › 산출물 › 한컴으로 확인」(기본 끔)은 모든 실행에 `DOCKET_HANCOM` 으로 넘어간다. 끄면 한글 스킬의 한컴 열기 검사 · 한컴 PDF · 한컴 hwp 변환이 한컴을 띄우지 않고(`hancom_worker.py` · `convert_hwp_hancom.ps1` 의 관문), 쪽 그림은 rhwp 로만 그린다.
  한컴 자동화 보안 모듈이 등록되지 않은 PC 에서는 한컴을 띄울 때마다 접근 확인 창이 떠서 기본을 끔으로 둔다. 켜면 한컴이 실제로 여는지 · 정확한 쪽 수를 확인한다.
  산출물 작성법 뽑기도 같은 꼴로 산출물 폴더에서 띄우되 모델은 구현 모델(비면 CLI 기본)이다. 뽑아 둔 글자를 프롬프트에 실어 보내 저장소를 읽지 않고, 동시에 둘까지만 띄운다. 뽑기는 「Claude 실행」 목록에 올라 멈출 수 있고, 응답은 산출물 폴더의 `runs/<run_id>.jsonl` 에 남아 「만드는 법」 탭의 「기록」으로 다시 펼친다. 지식베이스를 켠 프로젝트의 계획 · 대화 · 산출물 작성은 `kb/` 를 `--add-dir` 로 열어 뽑은 글자를 Read 로 읽게 한다.
- PDF 글자는 앱이 스스로를 `--docket-pdf-text` 인자로 한 번 더 띄워 뽑는다. 깨진 PDF 에서 패닉해도 그 파일만 건너뛴다(릴리즈는 `panic = "abort"`).
- 계획 · 문서 작성은 `--tools Read,Grep,Glob` 로 읽기만 허락하고, 결과는 `--json-schema` 로 받는다. 프로젝트 설정에서 켜 두면(기본) git · svn 의 조회 명령(log · diff · status · show · cat …)도 연다.
- 권한 모드는 실행마다 늘 적는다(읽기 `default` · 편집 `acceptEdits`). 적지 않으면 사용자 전역 설정의 기본 모드(`auto` 등)를 따라 열어 두지 않은 명령까지 통과할 수 있다.
- 「모두 허용」은 `--dangerously-skip-permissions` 를 쓰지 않는다. 명령 · 웹 · 스킬을 허용 목록으로 열어 일반 권한 판정 안에서 돌므로 프로젝트의 막을 목록과 전역 · 저장소 설정의 거부 규칙이 늘 앞선다. 승인 · 수정 요청 때 「이번만 모두 허용」을 고를 수도 있다.
- 막힌 호출은 stream-json 의 `permission_denied` 사건으로 잡아 실행 기록 · 변경 탭에 보인다. 허용 목록에 없어 막힌 것은 그 자리에서 「허용」으로 프로젝트 허용 목록에 넣는다. 실행마다 그때의 권한 · 실행한 명령 · 막힌 것을 기록 탭에 남긴다.
- 구현은 계획 세션을 `--resume` 으로 잇고 `--permission-mode acceptEdits`(또는 프로젝트 설정의 「모두 허용」)로 돈다. 이어 붙일 세션이 사라졌으면 새 세션으로 한 번 더 간다.
- 이슈 상세의 「대화」 탭에서 묻는 말은 같은 세션을 `--resume` 으로 이어 보낸다. 이미지는 입력칸에 붙여 넣거나 끌어 놓거나 첨부 단추로 고른다. 이슈 첨부 폴더에 들어가고, 보낼 때 그 경로를 Read 로 열어 보라고 함께 넘긴다.
  단계는 대화가 실제로 한 일로 옮긴다 — 이번 차례에 파일을 고쳤으면 결과 확인(구현 단계)으로, 메모 · 계획 · 보류 단계에서 설계가 정해졌으면 승인 대기(계획 단계)로. 설계가 정해졌는지는 Claude 가 답 맨 끝에 다는 `[단계:설계] <제목>` 줄로 알고, 그 답이 계획이 된다. 이 줄은 화면에서 걷어 낸다. 대화는 기본으로 구현과 같은 권한으로 돌아 바로 고칠 수 있고(고치라고 했을 때만 고치라고 지시한다), 바뀐 파일은 변경 탭에 쌓인다. 구현이 도는 중에도 기다리지 않고 바로 돌므로, 구현과 같은 파일을 고치라고 하면 서로의 수정이 겹칠 수 있다. 「읽기 전용」을 켜면 읽기 도구만 연다. 결과 형식(`--json-schema`)은 정하지 않고 글로 답을 받는다.
- 같은 탭 맨 위, 대화를 스크롤해도 움직이지 않는 줄에 세션 ID 가 보인다. 「터미널에서 잇기」는 프로젝트 폴더에서 `claude --resume <ID>` 를 띄우고(켠 터미널 플러그인이 있으면 그 정의대로 · 아래 「플러그인」, 없으면 Windows 터미널 새 탭, 그것도 없으면 새 콘솔), 「명령」은 그 명령을 복사한다. 세션 기록은 폴더별로 저장되므로 프로젝트 폴더에서 이어야 한다. 앱이 그 세션을 돌리는 동안에는 열지 않는다.
- 터미널에서 이어 간 차례는 세션 기록(`~/.claude/projects/<폴더>/<세션>.jsonl`)에서 읽어 대화 탭에 시간순으로 끼운다. 앱이 돌린 실행 시간 안의 차례는 앱 기록과 겹치므로 뺀다. 그 차례들이 고친 파일도 이슈의 변경에 담는다(상세 창을 열거나 창에 초점이 돌아올 때 읽는다) — 이슈를 만들기 전이나 마지막으로 되돌린 뒤보다 앞선 변경은 담지 않고, 고친 것이 있으면 앱 대화처럼 결과 확인으로 옮긴다. 변경 탭은 바뀐 파일이 구현 · 대화 · 터미널 중 어디서 왔는지 센다. 터미널에서 이으며 세션 ID 가 바뀌었으면 「바꾸기」에서 그 폴더의 최근 세션을 골라 다시 잡는다.
- 「읽기 전용」으로 보낸 질문은 프로젝트의 실행 줄에 서지 않는다. 고칠 수 있는 대화(기본)는 구현과 같이 줄을 선다.
- **대기열**: 그 이슈 · 대화가 실행 중(계획 · 구현 · 대화 무엇이든)일 때 보낸 질문은 `issue.json` 의 `queue` 에 쌓이고 입력칸 위에 한 줄씩 보인다. 실행이 끝나면 쌓인 것을 한 차례로 묶어 같은 세션에 이어 보낸다 — 글은 넣은 차례대로 빈 줄을 두고 잇고, 첨부는 겹치는 이름을 한 번만 넣고, 하나라도 고칠 수 있게 넣었으면 고칠 수 있는 권한으로 돈다. 실패한 차례 뒤에도 이어 보내지만, 사용자가 중지했거나 앱을 다시 켠 뒤에는 보내지 않고 「대기 N건 보내기」를 남긴다. 그때 새 질문을 보내면 남은 대기열 뒤에 붙여 함께 보낸다. 줄마다 「고치기」(입력칸으로 되돌림)와 빼기가 있고, 뺀 줄의 첨부는 첨부 폴더에서 치운다.
- 모델 · effort 는 메모 → 설정의 실행별 값 순으로 골라 `--model` · `--effort` 로 넘긴다. 비어 있으면 넘기지 않아 CLI 기본값으로 돈다. 제목 짓기 · 지식베이스 · 작성법 뽑기 같은 짧은 호출에는 `--effort` 를 붙이지 않는다.
- 첨부 폴더는 `--add-dir` 로 열어 준다. MCP 서버는 설정에서 켜지 않으면 `--strict-mcp-config` 로 하나도 띄우지 않는다.
- 바뀐 파일은 Edit · Write 도구 결과의 `structuredPatch` 로 기록한다. git · SVN 과 상관없이 Claude 가 고친 것만 보인다.

## 플러그인

사용자가 만들어 설치하는 확장이다. 플러그인은 앱의 네 자리에 끼어든다.

| 기여 (`contributes`) | 언제 | 하는 일 |
| - | - | - |
| `menus` | 이슈 카드 우클릭 · 상세 「더 보기」(`issue`) · 바뀐 파일 머리(`file`) · 사이드바 프로젝트(`project`)에서 누를 때 | 코드의 `on_command` 를 부르고, 돌려준 알림 · 열기 · 복사 · 마크다운 창을 앱이 그린다 |
| `events` | 계획 끝남 `planned` · 구현 끝남 `implemented` · 실패 `failed` · 되돌림 `reverted` · 완료 `done` · 보류 `dropped` · 산출물 새 판 `deliverable` | 코드의 `on_event` 를 부른다. 기다리지 않고 쏘기만 한다 |
| `settings` | 설정 › 플러그인 | 글 · 켜기 · 고르기 칸을 그리고, 값을 입력의 `settings` 로 넘긴다 |
| `terminal` | 「터미널에서 잇기」 | 아래 「터미널 기여」대로 바깥 터미널에서 세션을 잇는다. 코드가 없어도 된다 |

코드는 [Extism](https://extism.org) 플러그인(`.wasm`)이다. TS(js-pdk) · Rust · Go 로 짜서 `.wasm` 하나로 빌드한다. 앱은 그것을 샌드박스에서 돌린다.
- 화면에서는 돌지 않는다. 화면에 끼어드는 것은 위 선언과 돌려준 값뿐이다.
- 밖으로 나가는 길은 허락한 권한의 호스트 함수와 허락한 호스트로 가는 HTTP 뿐이다.
- WASI 는 켜되 폴더 · 환경 변수 · 표준 출력을 주지 않는다.
- 한 번 부르는 데 30초, 메모리 64MiB 를 넘으면 끊는다.

설정 › 플러그인은 두 묶음으로 보인다.

| 묶음 | 무엇 | 할 수 있는 것 |
| - | - | - |
| 코어 | 앱에 들어 있는 플러그인. 지금은 herdr 하나 | 스위치로 켜고 끄기만. 파일이 없고, 지우거나 같은 id 로 설치하지 못한다. 매니페스트를 파일로 바꿀 수 없어 권한 허락을 받지 않는다 |
| 커뮤니티 | `plugins/` 폴더에서 읽는 것(설치한 것 · 옛 정의) | 설치 · 켜고 끄기 · 권한 허락 · 지우기 |

### 꼴 · 설치

```text
plugins/<id>/plugin.json    매니페스트
plugins/<id>/plugin.wasm    코드 (메뉴 · 사건이 없으면 없어도 된다)
plugins-data/<id>/          settings.json(설정 칸 값) · kv.json(storage) · log.jsonl(실패 · docket_log)
```

```json
{ "id": "open-in-code", "name": "VS Code 로 열기", "version": "1.0.0", "apiVersion": 1, "main": "plugin.wasm",
  "description": "이 이슈에서 바뀐 파일을 VS Code 로 엽니다.",
  "permissions": ["issue:read", "process:code"],
  "contributes": {
    "menus": [{ "where": "issue", "command": "open", "label": "VS Code 로 열기", "when": "changes" }],
    "events": [], "settings": [{ "key": "webhook", "label": "웹훅 주소", "type": "text" }] } }
```

- 설정 › 플러그인의 「설치」에서 zip(맨 위나 한 단계 아래 폴더에 `plugin.json`) 이나 `plugin.json` 을 고른다.
  - 권한 · 기여를 보이고 허락받은 뒤, `plugin.json` 과 `main` 파일 둘만 `plugins/<id>/` 로 옮겨 켠다.
  - 같은 id 가 있으면 휴지통으로 옮기고 바꾼다. zip 항목은 폴더 밖을 가리키면 읽지 않는다.
- 「지우기」는 플러그인과 그 데이터를 휴지통으로 옮긴다. 매니페스트는 화면에서 고치지 않는다.
- `when` 이 `changes` 면 바뀐 파일이 있을 때, `session` 이면 세션이 있을 때만 누를 수 있다.
- 사건 · 메뉴가 실패하면 `log.jsonl` 에 남기고, 설정 줄에 「최근 7일 실패 N건」을 보인다.
  - 사건 실패는 이슈 이력과 알림에 올리지 않는다. 이슈를 건드리면 보드 순서가 바뀌고, 사건마다 실패하면 알림이 쏟아진다.
  - 사용자가 누른 메뉴의 실패는 오류 알림으로도 띄운다.
- 예제: `examples/plugins/open-in-code` (TS → wasm). 타입은 `examples/plugins/docket-plugin.d.ts`.
  - 빌드: `npm install` 뒤 `npm run build`. [extism-js](https://github.com/extism/js-pdk) 와 binaryen 이 PATH 에 있어야 한다.
  - 앱 저장소에서는 이 빌드를 돌려 보지 않았다.

### 권한

설치할 때 허락한 권한은 `settings.json` 의 `pluginGrants` 에 남는다. 매니페스트의 권한이 이보다 넓어지면 「권한 허락」을 다시 누르기 전에는 부르지 않는다. 설치한 뒤 파일만 바꿔 권한을 몰래 늘리지 못하게 하려는 것이다.

| 권한 | 열리는 것 |
| - | - |
| (없음) | `docket_log`. 입력에는 프로젝트 id · 이름과 이슈 id · 번호만 실린다 |
| `issue:read` | 입력에 이슈 · 산출물 내용(메모 · 계획 · 결과 · 바뀐 파일 · 오류)과 프로젝트 경로가 실린다. `docket_issue_get` |
| `notify` | `docket_notify` 앱 안 알림 |
| `open` | `docket_open` · 돌려주는 값의 `open` (파일 · 폴더 · http(s) 주소를 기본 프로그램으로) |
| `storage` | `docket_kv_get` · `docket_kv_set` (자기 `kv.json` · 1MB 까지) |
| `process:<이름>` | `docket_run` 으로 그 이름의 실행 파일만(PATH 에서 `.exe` · `.cmd` · `.bat`). 25초가 지나면 끈다 |
| `http:<호스트>` | Extism 의 HTTP 요청을 그 호스트로만 (`*.example.com` 꼴 가능) |

- **`process:<이름>` 은 실행 파일만 묶고 인자는 거르지 않는다.** `cmd` · `powershell` · `node` 처럼 무엇이든 돌릴 수 있는 프로그램을 허락하면 사실상 모든 것을 허락하는 셈이다. 허락 창이 그런 이름을 빨갛게 보인다.
- `issue:read` 와 `http:` 를 함께 허락하면 플러그인은 읽은 메모 · 경로를 그 호스트로 보낼 수 있다.

### 입력 · 돌려주는 값

`on_event` · `on_command` 모두 JSON 글 하나를 받는다.

```json
{ "apiVersion": 1, "event": "implemented", "command": "", "where": "",
  "plugin": { "id": "slack-notify", "version": "1.0.0" },
  "project": { "id": "…", "name": "calc", "path": "D:\\work\\calc" },
  "issue": { "id": "…", "number": 4, "title": "더하기 고치기", "status": "review",
             "changes": [{ "path": "D:\\work\\calc\\calc.py", "rel": "calc.py", "kind": "edit" }] },
  "deliverable": null, "file": "", "settings": { "webhook": "https://hooks.slack.com/…" } }
```

`on_command` 는 `{ "toast", "open", "copy", "markdown", "title" }` 를 돌려준다(모두 비어도 된다). `markdown` 은 앱의 마크다운 표시로 창에 그리고, 원시 HTML 은 그리지 않는다.
호스트 함수의 입력 · 출력 꼴은 `examples/plugins/docket-plugin.d.ts` 와 `src-tauri/src/plugin_host/api.rs` 머리말에 있다.

### 하지 못하는 것

| 하고 싶은 것 | 되지 않는 까닭 | 대신 |
| - | - | - |
| 보드에 열 · 탭 · 배지 그리기, 화면에 스크립트 띄우기 | 화면 기여는 선언형만 받는다. 주 창은 앱의 모든 명령을 부를 수 있어 플러그인 스크립트를 들이면 그 권한을 빌려 쓴다 | 메뉴 + 마크다운 창 |
| 사건에서 완료 · 승인 막기 | 사건은 기다리지 않는다. 플러그인이 느리거나 죽어도 이슈 흐름이 멈추지 않게 한다 | 실패를 알림으로 보내 사람이 판단 |
| Claude 프롬프트 · 권한 바꾸기 | 권한 판정은 앱이 맡는다 | 어휘 사전 · 지식베이스 · 저장소 지침 |
| Claude 의 도구 호출마다 검사 | Claude Code 가 하는 일이다 | Claude Code hooks (`settings.json`) |
| 메모 만들기 · 이슈 고치기 · 타이머 | API 1판에 쓰기 권한과 주기 사건이 없다 | — |

### 터미널 기여

`contributes.terminal`, 또는 옛 정의 `plugins/<id>.json`(`kind: "terminal"` 인 2026-10-29 전의 꼴. 터미널 기여 하나짜리로 읽고, 이미 켜 둔 것이라 권한을 허락한 것으로 본다).
켜 두면 「터미널에서 잇기」가 그것으로 열고, 버튼 이름도 「<이름> 에서 잇기」로 바뀐다. 실행 파일은 권한에 `process:<이름>` 으로 적는다.

```json
{ "id": "herdr", "name": "herdr", "version": "1.0.0", "apiVersion": 1, "permissions": ["process:herdr"],
  "contributes": { "terminal": {
    "exe": "herdr",
    "probe": ["workspace", "list"],
    "focus": ["agent", "focus", "docket-{session_short}"],
    "attach": [["tab", "create", "--cwd", "{cwd}", "--label", "{title}", "--focus"],
               ["agent", "start", "docket-{session_short}", "--kind", "claude",
                "--pane", "{out.result.root_pane.pane_id}", "--", "--resume", "{session}"]],
    "launch": [], "hostWt": true, "attachAfterLaunch": true } } }
```

- `exe` 는 이름만 적으면 PATH 에서 찾는다(확장자를 빼면 `.exe` · `.cmd` · `.bat` 를 붙여 본다).
- 인자 안의 자리표시 `{cwd}` 프로젝트 폴더 · `{claude}` claude 실행 파일 · `{session}` 세션 ID · `{session_short}` 세션 ID 앞 8자(영문 소문자 · 숫자) · `{title}` `#번호 제목` 을 채운다. 셸을 거치지 않고 인자 배열 그대로 넘긴다.
- `probe` 를 창 없이 돌려 3초 안에 0 으로 끝나면(켜 둔 것이 있으면) `focus` 를 먼저 돌려 0 이면 거기서 끝내고(이 세션이 이미 떠 있다), 아니면 `attach` 로 붙인다. 켜 둔 것이 없거나 `attach` 의 첫 단계가 실패하면 `launch` 로 새로 띄운다. `probe` · `attach` 를 비우면 늘 `launch` 다.
- `attach` 는 단계 하나면 `["a", "b"]`, 여럿이면 `[["a"], ["b"]]` 로 적는다. 둘째 단계부터는 `{out.경로}` 로 앞 단계가 낸 JSON 의 값을 받는다. 둘째 단계부터 실패하면 새로 띄우지 않고 herdr 가 낸 오류를 그대로 알린다(앞 단계가 만든 탭이 남아 있기 때문이다).
- `attachAfterLaunch` 를 켜면 `launch` 로 띄운 뒤 20초 동안 `probe` 가 0 이 되기를 기다렸다가 `attach` 를 돌린다. herdr 처럼 띄우는 인자로 명령을 받지 않는 프로그램도 세션을 잇는다.
- `hostWt` 를 켜면 `launch` 를 Windows 터미널 새 탭(`wt.exe -d {cwd}`) 안에서 띄운다. 화면이 있어야 도는 프로그램은 창이 따로 없으면 바로 끝난다.
- 켠 플러그인을 쓸 수 없으면(실행 파일을 못 찾음 · 모르는 자리표시 · 정의를 읽지 못함 · 권한을 다시 허락해야 함) Windows 터미널로 넘어가지 않고 오류를 낸다. 켜 둔 연동이 몰래 빠지지 않게 하려는 것이다. 켠 터미널 플러그인이 둘이면 코어를 먼저, 이어 폴더 · 파일 이름 순으로 앞의 것을 쓴다.
- `{session}` 이 어느 인자에도 없으면 설정 화면이 「세션을 잇지 않고 프로그램만 엽니다」라고 알린다.
- 위 정의가 코어 플러그인 herdr 다. 설정 › 플러그인의 「코어」에서 켜기만 하면 된다. 켜 둔 herdr 에는 이슈마다 새 탭 「#번호 제목」을 만들어 `claude --resume` 으로 잇고, 그 세션이 이미 떠 있으면 그 탭으로 옮긴다. herdr 가 꺼져 있으면 Windows 터미널에 띄운 뒤 붙인다. claude 는 herdr 가 PATH 에서 찾는다(설정의 claude 경로를 쓰지 않는다).
- 예전에 「herdr 정의 만들기」로 만든 `plugins/herdr/` · `plugins/herdr.json` 은 앱이 시작할 때 내용을 따지지 않고 앱 데이터의 휴지통 폴더(`trash/<시각>-플러그인-herdr`)로 옮긴다. 켜 둔 상태는 그대로 코어로 이어진다. 인자를 손으로 고쳐 쓰려면 다른 id 의 커뮤니티 플러그인으로 설치한다.

## 개발

직접 빌드하려면 Node.js 24 LTS(최신 패치)와 Rust 1.99 이상 stable(`rustup update stable`)이 필요하다. `node -v` · `rustc -V` 로 확인한다.
설치 파일로 깐 앱은 둘 다 필요 없다. Node 판이 맞지 않으면 npm 은 경고만 내고 설치를 이어 간다.

```bash
npm install
npm run tauri dev       # 개발 실행
npm run tauri build     # 설치 파일 (src-tauri/target/release/bundle/nsis)
npx tsc --noEmit        # 화면 타입 검사
cd src-tauri && cargo check
```

- 개발 빌드에서는 주소로 첫 화면을 고를 수 있다: `npm run tauri dev -- --config '{"build":{"devUrl":"http://localhost:1420/?view=claude"}}'` (`view` · `project` · `issue` · `deliverable` · `talk`). 지식베이스는 `view=knowledge`.
- 시험용 데이터로 띄우려면 `DOCKET_HOME` 을 빈 폴더로 준다.
- Tauri 없이 화면만 보려면 `npx vite --port 1430` 을 띄우고 `http://localhost:1430/preview.html?project=pcalc0000001&view=board` 를 연다.
  가짜 데이터(`src/preview/fixtures.ts`)로 모든 단계의 카드 · 상세 창이 나온다. `&issue=<id>` · `&theme=light` · `&empty=1` 을 붙여 상태를 고른다. 배포 빌드에는 들어가지 않는다.
- 실제 CLI 로 계획 → 구현, 산출물 파일 만들기를 확인하는 시험(비용이 든다): 일부러 틀린 `calc.py`(`add` 가 `a - b` 를 돌려준다)가 든 폴더를 만들고
  `DOCKET_TEST_PROJECT=<폴더> cargo test -- --ignored --nocapture`
- 템플릿 글자 뽑기를 실제 오피스 파일로 볼 때: `DOCKET_SAMPLES="<파일1>;<파일2>" cargo test sample -- --ignored --nocapture`

### 릴리즈 · 자동 업데이트

- `package.json` · `src-tauri/Cargo.toml` · `src-tauri/tauri.conf.json` 의 버전을 함께 올리고 커밋한 뒤 `git tag v<버전> && git push origin v<버전>`.
  `.github/workflows/release.yml` 이 Windows 설치 파일 · 서명 · `latest.json` 을 릴리즈에 올린다.
- 설치된 앱은 켤 때와 켜 둔 동안 1시간마다(창으로 돌아왔을 때 1시간이 지났으면 그때도) `releases/latest/download/latest.json` 을 보고, 새 판이면 알림의 「설치」로 받아 깔고 다시 켠다.
  간격은 `src/lib/updater.ts` 의 `CHECK_EVERY_MS` 이고, 「설정 › 업데이트 › 자동으로 확인」으로 끈다. 개발 판(`tauri dev`)에서는 자동 확인을 하지 않는다.
- 설치 위치는 사용자 전용 `%LOCALAPPDATA%\Programs\docket` 이다(UAC 없음). Tauri 기본값(`%LOCALAPPDATA%\docket`)을 바꾸려고 NSIS 템플릿을 `src-tauri/windows/installer.nsi` 로 복사해 그 한 줄만 고쳤다.
  Tauri CLI 를 올리면 그 판의 원본을 다시 받아 같은 줄만 고친다(파일 머리말).
- 업데이트 서명 키는 `~/.tauri/docket.key`(비밀번호 없음)이고, 저장소 비밀 `TAURI_SIGNING_PRIVATE_KEY` 에 같은 내용이 있다.
  **키를 잃으면 이미 깔린 앱은 더는 업데이트를 받지 못한다** — 공개 키가 앱 안(`tauri.conf.json` 의 `plugins.updater.pubkey`)에 박혀 있다.
